## ANALIZY / DECYZJE USERA (bez kodu w X26)

**A1. Strzałka wstecz na paywallu (soft mode).** Stan: hard gate tylko dla świeżego usera bez treningów; wtedy strzałki NIE ma. Strzałka pojawia się w trybie soft (user z historią) i to jest poprawne: monetyzację trzymają bramki akcji (start treningu, kreator planu). Rekomendacja: ZOSTAWIĆ. Świeży user i tak nie ominie paywalla; zabranie strzałki userowi z historią zablokowałoby dostęp do jego danych (ryzyko App Review 5.1.1 i skarg).

**A2. Zakupy przez web + odzyskiwanie zakupu.** Dziś: brak web billing (tylko StoreKit/Play przez RevenueCat), ALE entitlement jest per konto Strength Save (RC appUserID = uid, webhook → Firestore), więc "odzyskanie zakupu przez zalogowanie" JUŻ DZIAŁA między urządzeniami i platformami. Do rozważenia później: RevenueCat Web Billing (Stripe) — osobny projekt (podatki/OSS, ceny web, paywall web). Nie wdrażamy w X26 (zgodnie ze słowami usera "nie musimy na razie wdrażać").

**A3. Cennik: konflikt decyzji.** X25 (2026-08-10) ustalił podniesienie rocznego 99,99 → 119,99 zł (zmiana w ASC planowana od 2026-08-12). Dziś (2026-08-11) user ocenił widoczne 99,99/14,99 jako "jak najbardziej w porządku". Wymaga jednoznacznej decyzji usera: zostawić 99,99 (anulować zmianę ASC) czy jednak 119,99. Paywall i tak pokazuje ceny dynamicznie ze sklepu — kod nie blokuje żadnej opcji.
