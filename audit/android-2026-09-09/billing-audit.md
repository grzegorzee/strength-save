Pending-payment behavior and store management URLs follow the official [RevenueCat error guidance](https://www.revenuecat.com/docs/test-and-launch/errors) and [subscription management guidance](https://www.revenuecat.com/docs/subscription-guidance/managing-subscriptions). ## What controls access and what controls charging

| Situation | Application access | Charging |
| --- | --- | --- |
| Normal native account | `useSubscription.ts:88–90`: admin OR valid server subscription OR current owner's RC `entitlements.active.pro`. Native iOS and Android use the same rule. | Only the user's store purchase flow starts a purchase. Firestore grants/webhooks cannot charge. |
| Free trial | Store-confirmed eligible free option; Android purchases the exact displayed `SubscriptionOption`. PRO requires actual entitlement. | Trial duration, renewal price and eligibility come from Play/RC products. Store handles automatic renewal after trial. |
| Pending initial payment | No locally invented PRO. UI explains how to finish; CustomerInfo/webhook can later confirm access. | Payment is unfinished; an attempted purchase is not proof of collection. |
| Cancel renewal | Access remains through confirmed paid/trial time. | Store stops future renewals; app management link opens the responsible store. |
| Grace / account hold | Authoritative RC access plus entitlement expiry preserves grace; hold without access clears the store mirror. | Store owns payment retries, not this application. |
| Admin / complimentary grant | Admin/active comp grants PRO; webhook store state is retained underneath comp. | No store charge follows from a grant. |
| Same Strength Save account on another platform | Firebase UID is RC appUserID; current RC entitlement and server mirror carry access across devices/stores. Existing PRO redirects away from Paywall. | App does not initiate another purchase merely because platform changes. |
| Logout/account switch | SDK identity mutations are serialized, requested owner published synchronously, reads and mutations checked before/after; old CustomerInfo hidden by UID/generation. | No old account operation may start under a new SDK identity. |

`UserContext.hasAppAccess` is account status/administrative admission, distinct from PRO. `useHardPaywall` deliberately fails open for reading historical data if the workout lookup is unavailable; that does not grant PRO to premium actions. Web/Garmin rely on the server mirror, which is why BILL-03 matters even when a phone has a valid SDK entitlement.
